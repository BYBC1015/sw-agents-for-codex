## Use Protocol

- Read this file only when the user asks for high-level aesthetic repositories, visual research sources, moodboard sources, or aesthetic calibration.
- Use at most 1-3 sources per project phase. More sources usually blur taste instead of improving it.
- Convert references into neutral language: camera position, shot size, lens feel, subject scale, light quality, color relationship, texture, layout density, typography hierarchy, rhythm, and negative constraints.
- Do not copy exact frames, layouts, logos, distinctive characters, source text, or proprietary graphic devices into deliverables.
- For GitHub curated lists, treat them as discovery maps rather than taste authorities; verify the downstream source before adopting it.
- For AI image/video generation, pass only the extracted visual language into prompts; do not ask the model to reproduce a named source image.

## Quality Caveats

| Source type | Strength | Weakness | SW handling |
| --- | --- | --- | --- |
| Film-frame libraries | Strong camera, lighting, blocking, palette, and mood references | Easy to overfit to famous frames or named directors | Extract only neutral shot language and combine with the user's brief |
| Brand/type/web curation | Strong layout, hierarchy, type pairing, and visual-system discipline | Trend-heavy sources can make output look generic if copied too directly | Use as constraint vocabulary, not as final style |
| Motion/video curation | Strong rhythm, transition, pacing, and sound-image thinking | Often lacks full production context or budget reality | Extract timing and movement rules, then adapt to actual platform and duration |
| GitHub curated lists | Good discovery maps and long-tail resource finders | Mixed quality; many links are not taste-filtered | Use for search expansion only; pick downstream sources manually |
| Moodboard/bookmark platforms | Fast signal for current taste and texture | Can become a pile of unrelated images | Limit to 1-2 visual levers per phase |
