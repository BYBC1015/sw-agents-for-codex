# SW V1.16.1 / Canvas 0.4.1

The saved Canvas page reported `ERR_CONNECTION_REFUSED`: its server was no longer running, while the project and conversation binding remained intact. There was no recorded crash traceback, so the exact cause of that exit is unconfirmed.

The Windows launcher now creates a hidden background process through local WMI, outside the calling shell's process tree. It forwards only required system/media environment settings, checks the existing service identity, and records startup/exit diagnostics. It does not install a scheduled task or login startup. After reboot, run the launcher once and refresh the saved page; browser refresh cannot start a local service.

Canvas recovery instructions now restart the service without creating or rebinding a project. Banana's former default inline-image reply conflicted with Canvas's link-only receipt. In an explicitly bound Canvas workflow, registered results now use a short text receipt and Canvas link. Explicit chat-preview requests and mandatory native tool output retain their behavior. Old images remain in chat history; this patch makes no promise about the host's context compaction or latency.

Validation covers actual server survival after launcher exit and Windows caller-tree termination, repeat startup with the same PID/project, occupied-port protection, and Unicode paths/media-root configuration. Windows lifecycle testing is now included in CI alongside Linux Canvas/browser and SW checks. No paid generation, media upload, database migration or customer-media publication is involved.
