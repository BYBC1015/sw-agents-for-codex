# SW Relay Server Takeover Handoff

日期：2026-07-02

用途：这是一份“服务器接管/调用”专用交接文档，只用于让新的 Codex 对话理解并安全接管之前为 SW 图片/视频 URL 中转购买的服务器。它不是 SW_V1.0 完整项目交接，也不是服务器密钥文件。

## 1. 当前已知信息

- 服务器当前主要用途：SW media uploader，用于把本地图片/视频中转成下游 AI 工具可访问的公网 URL。
- 已知公网地址：`123.56.255.86`
- 已知上传入口：`http://123.56.255.86/upload`
- 已知公开访问前缀：`http://123.56.255.86/u`
- 本机私密配置路径：`~/.config/sw-media-uploader/config.json`
- 相关环境变量：`SW_RELAY_TOKEN`
- 仓库内调用脚本：`url-relay/scripts/url_relay.py`
- 相关 SW 工具 skill：`url-relay/SKILL.md`

注意：以上是从当前 SW URL Relay 规则和仓库配置中整理出的“已知调用信息”，不是一次实时服务器巡检结果。接管前必须先只读巡检服务器现状。

## 2. 绝对不要写进对话或仓库的内容

- 上传 token
- SSH 私钥
- 云服务器控制台密码
- root 密码
- 宝塔/面板账号密码
- 数据库密码
- 任何 `.env`、`secrets.json`、`config.json` 里的真实密钥值

如果新对话需要访问服务器，让 Codex 优先使用本机已有 SSH 配置、云厂商控制台、或用户明确提供的临时安全凭证。不要把长期密钥直接贴进文档或代码仓库。

## 3. 现有链路不能随便破坏

除非用户明确说“废弃原中转服务”，否则接管服务器时必须保留：

- `POST /upload`
- `GET /u/...`
- 当前上传 token 校验机制
- 已有文件清理机制
- URL Relay 本机配置兼容性

原因：Seedance、Banana Pro、其他图生视频或图片工具可能仍依赖这个服务器把本地素材变成公网 URL。

## 4. 新对话接管服务器的第一步

新的 Codex 对话不要一上来部署网站。先做只读巡检：

1. 确认服务器访问方式：SSH alias、IP、用户名、端口、密钥位置或云厂商控制台入口。
2. 确认当前系统：发行版、版本、磁盘、内存、CPU、时区。
3. 确认正在运行的服务：Web 服务、反向代理、上传服务、清理任务、容器、systemd 服务。
4. 确认开放端口和防火墙：至少检查 22、80、443，以及任何已有服务端口。
5. 找到 `/upload` 和 `/u` 的实现位置，但先不要改。
6. 备份现有 Nginx/Caddy/Apache 配置、服务文件、上传服务目录和清理脚本。
7. 给用户汇报“能否在不影响中转服务的前提下加网站”。

## 5. 推荐的网站部署方式

优先顺序：

1. 新域名或子域名 + 独立站点目录 + 独立反向代理规则。
2. 独立服务端口 + Nginx/Caddy 转发。
3. Docker/Compose 独立容器，避免污染原中转服务。
4. 静态网站优先放在独立目录，例如 `/var/www/<site-name>`。
5. 不建议把新网站直接塞进现有 `/upload` 或 `/u` 服务代码里。

保守原则：

- `/upload` 和 `/u` 保持原样。
- 新网站走独立域名、独立 location、独立服务或独立容器。
- 先部署一个最小健康页，再部署正式站点。
- 每次修改反向代理配置前先备份。
- 修改后同时测试网站和原中转上传链路。

## 6. 建站前需要用户确认的事项

只问必要问题：

- 这个网站要公网访问，还是只给自己/团队访问？
- 是否已有域名？如果没有，是否接受先用 IP 或临时域名测试？
- 是否需要 HTTPS？
- 是否必须保留原 URL Relay 服务不中断？
- 网站类型：静态页、后台管理、文件服务、API、展示站、还是应用服务？

如果用户说“你定”，默认方案：

- 保留原中转服务。
- 先做独立静态站点或独立容器。
- 先用 IP/端口或临时反向代理路径测试。
- 等用户确认域名后再上 HTTPS 和正式发布。

## 7. 安全边界

- 不要为了部署网站关闭防火墙。
- 不要直接覆盖 `/etc/nginx/nginx.conf` 或主配置，优先新增站点配置。
- 不要删除上传目录或清理脚本。
- 不要扩大上传服务权限。
- 不要把上传目录当作网站根目录。
- 不要公开目录索引，除非用户明确需要文件列表。
- 如果服务器位于中国大陆云厂商，公开网站前需要考虑域名备案、HTTPS、内容合规和云厂商安全策略。

## 8. 接管后的建议产物

新的 Codex 对话接管后，应输出一份简短状态卡：

- 服务器访问方式是否可用
- 当前系统和 Web 服务
- 原 URL Relay 是否仍可用
- 新网站部署策略
- 需要用户确认的域名/HTTPS/用途
- 下一步是否开始部署
